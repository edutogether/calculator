# InKY Calculator를 React + TypeScript + Vite로 전환한다 (화면·동작은 한 픽셀도 바꾸지 않는다)

> 팀장 지시("intent 먼저 쓰고 보고한 뒤 착수")에 따라 이 문서를 먼저 올렸고,
> 2026-09-25 팀장 확인("0단계부터 시작하세요")을 받아 `in-progress`로 올렸다.

## 문제

org 여덟 앱 가운데 React + TypeScript로 전환되지 않은 곳은 이 앱과 AI Ways Incheon PC
화면뿐이다. 대표님이 "전부 전환해"로 확정했고 `_shared/CONVENTIONS.md` 4.3에 org 규칙으로
적혔다. 이 앱만 스택이 달라서 생기는 비용은 org 차원의 것이다 — 검사·린트·빌드·배포 절차가
이 저장소에서만 다르다.

지금 구조: `index.html` 한 파일(1,301줄)에 CSS(약 355줄)와 계산 로직(인라인 `<script>` 하나,
약 830줄, 이름 있는 함수 27개, `id` 49개)이 다 들어 있다. 첫 종합감사 10/10을 받았고
**고장 난 곳은 없다.** 그래서 이 전환이 이기려면 "지금과 같다"를 증명할 수 있어야 한다.

**위험을 한 번 적어 둔다(결정은 이미 내려졌다).** 이 앱은 11월 14일 행사에 한 번 쓰이고
11월 15일에 내려간다. 전환의 이득(앞으로 들어올 수정을 받기 쉬운 구조)이 쓰일 기간은 짧고,
회귀 위험은 행사 직전에 몰린다. 그래서 아래의 기준선 대조와 "배포는 팀장 확인 뒤"를
전환 작업 자체보다 먼저 세운다.

## 원하는 결과

전환이 끝났을 때:

1. 소스가 React 19 + TypeScript(strict) + Vite로 되어 있고, eslint가 CI에서 돈다.
2. **전환 전 기준선과 전환 후 결과를 대조했을 때 차이가 0건이다** — 아래 "증명 방법"의
   모든 층에서. "비슷하다"가 아니라 대조 도구가 0을 낸다는 뜻이다.
3. **이미 밖에 나가 있는 것이 전부 그대로 동작한다**: 카카오톡으로 나간 `#q=` 견적 링크는
   전환 전과 같은 화면으로 열리고, 같은 견적 상태는 전환 전과 **글자 하나 다르지 않은**
   `#q=` 문자열을 만든다.
4. Firebase Hosting에는 **빌드 산출물만** 올라간다 — 배포 로그 기대값은 지금처럼
   `found 2 files`(`index.html` + `og.jpg`).
5. 기존 검사(CSP 해시·권장안·부호·대비·공유 카드·vitest 15개)가 전부 새 구조를 대상으로
   **이빨을 가진 채** 돈다 — 옮긴 뒤 각각 일부러 깨뜨려 실패하는 것을 다시 확인한다(§5.4).

## 영향받는 사용자·시스템

- **실사용자 있음**: 부스 물품 견적을 짜는 교사·운영진. 경로가 넷이다(`CLAUDE.md` 표) —
  호스팅 웹, **내려받은 HTML 파일을 직접 열기**, 카톡 파일 미리보기(JS 차단 → `#nojs` 카드).
  셋 모두 지금과 같게 동작해야 한다. (클로드 아티팩트 사본은 2026-09-25 대표 결정으로
  전환 **전에** 따로 걷어냈다 — 기준선은 그 뒤에 찍는다.)
- **이미 퍼진 `#q=` 링크**: 회수할 수 없다. 인코딩(JSON → UTF-8 → base64 URL-safe)이
  한 바이트라도 바뀌면 옛 링크가 깨진다.
- **배포 파이프라인 전체가 바뀐다**: `firebase.json`의 `public`이 `.` → `dist`, CI에 빌드 단계,
  CSP 해시 대상이 빌드 산출물로. 이 셋이 한 묶음으로 가지 않으면 배포가 깨지거나
  **조용히 옛 파일이 서빙된다.**
- **검사 스크립트 6개와 vitest 헬퍼가 전부 `index.html`을 직접 읽는다**(정규식으로
  `const D=`·`signed()`·`.cap` 등을 떼어 냄). 번들·압축된 산출물에서는 그 정규식이
  빗나간다 — 옮기지 않으면 검사가 전부 실패하거나, 더 나쁘게는 **빈 게이트**가 된다.
- 저장소는 이것 하나다. Firebase 프로젝트·사이트 ID(`inky-calculator`)는 건드리지 않는다.

## 제약

협상 대상 아님. 지킬 수 없다는 걸 발견하면 완화하지 않고 멈추고 팀장에게 보고한다.

- 🔴 **화면·동작이 한 픽셀도 달라지지 않는다.** 보이는 값뿐 아니라 계산 결과·반올림·절사·
  빈 입력 처리·부호·색 판정, 그리고 §5.5의 비가시 값(`id` 집합, `aria-*`, `role`, `title`,
  `<meta>` 14개 공유 카드 태그 포함, `lang`, 입력칸 `type`/`inputmode`/`value`, 탭 순서)까지.
- 🔴 **"언어가 바뀌었으니", "옛 코드가 지저분해서"는 달라져도 되는 이유가 아니다.**
  "깔끔하게"가 허용하는 것은 소스 구조뿐이고, 결과물과 충돌하면 결과가 이긴다.
- 🔴 **전환하면서 고치지 않는다.** 고칠 것이 보이면 아래 "전환 중 발견한 것" 목록에만 적고,
  전환이 끝난 뒤 따로 다룬다. (예: `app.md`의 "남는 예산은 `-`로 빨강" 문단은 뒤의 `signed()`
  절과 모순된다 — 문서 문제지만 이것도 이 작업에서 고치지 않는다.)
- **§15**: "일단 동작하게"·"차선책"·"우회로"·"나중에 제대로" 금지. 범위를 줄이는 것은 대표님
  결정이다.
- **전환 전 freeze 태그** `calculator-freeze-20260925-pre-react`를 전환 직전 `main`에 찍는다
  (그 위에 얹힌 것은 이 intent 문서 커밋뿐이라 제품은 `e6cd1ab`와 같다).
  **푸시 금지 지시**에 따라 태그도 로컬에만 찍고, 원격에는 팀장 확인 때 함께 올린다.
- **전환 작업은 로컬 브랜치 `conv/react-ts`에서 한다.** 이 intent 문서만 `main`에 로컬
  커밋한다. 어느 쪽도 푸시하지 않는다 — 푸시·배포는 팀장 확인 뒤.
- **브라우저 검증은 세션 자신의 브라우저로**(내부 Browser 패널 또는 이 세션의 `--user-data-dir`로
  띄운 헤드리스 Chrome). 대표님 크롬은 쓰지 않는다 — 이 앱은 로그인이 없어 쓸 이유가 없다.
  띄운 것은 끝나면 정리한다(§17).
- **이 앱의 기존 규칙은 전부 유효하다**(`.claude/rules/app.md`): CSP는 응답 헤더로만,
  `'unsafe-inline'` 금지, 인라인 `style=`·`onclick=` 금지, `M.auto` 기본값 `false`,
  외부 스크립트는 cdnjs xlsx(SRI)와 Google Fonts뿐, `.moutw`의 `flex:0 0 auto` 등.

## 이 앱에서 전환이 깨뜨리기 쉬운 것 — 구조로 막는다

형제 앱들에는 없는, 이 앱에만 있는 함정이다.

| # | 무엇 | 왜 깨지는가 | 막는 방법 |
|---|---|---|---|
| A | **단일 파일** | Vite 기본 산출물은 `index.html` + `assets/*.js`·`*.css`다. 호스팅은 되지만, **내려받은 HTML 파일을 직접 열면**(`file://`) 스크립트 경로가 풀리지 않아 빈 화면이 된다 | JS·CSS를 산출물 `index.html` 안에 인라인하는 빌드(`vite-plugin-singlefile` 류). 미결 질문 1 |
| B | **CSP sha256 해시** | 인라인 블록이 번들로 바뀌면 해시가 전부 바뀐다 | `check-csp.js`를 `dist/index.html` 대상으로 옮기고, 해시 갱신을 빌드 뒤 단계로 고정 |
| C | **`#nojs` 카드 + `html.js` 토글** | 카톡 미리보기는 JS를 안 돌린다. 카드는 정적 HTML이어야 하고, `html.js`는 첫 그림 전에 붙어야 깜빡임이 없다. React가 붙는 시점은 그보다 늦다 | 카드와 토글 스크립트는 React 밖, 지금 자리 그대로 둔다 |
| D | **`#q=` 호환** | `stateStr()`의 필드 순서·JSON 직렬화가 바뀌면 문자열이 바뀐다 | 기준선에서 여러 상태의 `#q=` 문자열을 기록해 두고, 전환 후 **같은 상태 → 같은 문자열**, **옛 문자열 → 같은 화면**을 둘 다 대조 |
| E | **xlsx(CDN 전역 `XLSX`)** | npm 패키지로 바꾸면 번들이 약 1MB 커지고 로딩이 바뀐다 | 지금처럼 SRI 걸린 CDN 스크립트 그대로. 코드는 전역 `XLSX`를 타입만 선언해 쓴다 |
| F | **인쇄 A4 6쪽** | DOM 구조·클래스가 조금만 바뀌어도 쪽 나눔이 바뀐다 | 기준선·결과 모두 `Page.printToPDF`로 쪽수와 쪽별 이미지를 대조 |
| G | **검사 정규식** | 위 "영향받는" 참고 | 각 검사를 새 대상으로 옮긴 뒤 변이로 이빨 재확인. 빈 대상이면 실패하게(§21-1) |

## 증명 방법 — "같다"의 근거

**전환 코드보다 먼저** 대조 도구를 만들고 기준선을 찍는다. 전환을 시작한 뒤에 찍은 기준선은
이미 오염돼 있다.

1. **화면**: 뷰포트 4종(375×812 폰 / 768×1024 태블릿 / 1440×900 PC / **759px**·**761px** —
   760px 미디어쿼리 경계 양쪽) × 라이트·다크 × 상태 여럿(첫 화면 권장안 / 전부 끔 /
   예산 초과 / `#q=` 복원 / 탭 ⓪~⑤ 각각 / 안내창 열림 — 인당 상한·40% 상한·인쇄 안내).
   스크린샷 픽셀 차이 **0**. 그리고 계산된 CSS·위치·크기를 요소별로(`id`·경로 키로 짝지음,
   문서 순서로 짝짓지 않는다).
2. **값**: 화면에 찍힌 모든 금액·집행률·부호·색 클래스, 협의회비 자동 계산 결과, 빈 입력·
   음수·문자열 입력 처리, 인당 상한 초과 입력 시 보정값.
3. **밖으로 나가는 것**: `#q=` 문자열(D), 엑셀 저장 파일의 시트·셀 값(파일 바이트는 생성 시각이
   들어가 비교하지 않는다), 공유하기가 넘기는 `title`·`url`, 인쇄 PDF 쪽수·쪽별 이미지(F).
4. **동작**: 링크·버튼 전부(탭 전환, 수량 ±, 자동 계산, 엑셀 가져오기 왕복, `#nojs` 카드 링크의
   `href`), 파비콘 흑백 전환, `prefers-reduced-motion`, 선택 목록 스크롤 가두기.
5. **경로 셋**: 호스팅(프리뷰 채널), 내려받은 파일 직접 열기, JS 끈 상태(`#nojs`).
6. **대조 도구 자체도 검증한다**: 일부러 1px 옮기기·색 하나 바꾸기·`id` 하나 지우기·`#q=` 필드
   순서 바꾸기를 넣어 도구가 잡는지 확인한다.

기존 vitest 15개는 **전환 전 `index.html`과 전환 후 `dist/index.html` 양쪽에 같은 테스트를
돌려** 둘 다 통과해야 한다 — 테스트를 새 구조에 맞춰 약하게 고치는 것은 허용하지 않는다.

## 단계

   `applyState` 등)부터. 대조 0건.
3. React 껍데기 — 같은 DOM을 그리게. 대조 0건.
4. 검사·테스트 재정비(변이로 이빨 재확인), eslint, 문서(`AGENTS.md`·`README.md`·`app.md`·
   `CHANGELOG.md`). `CLAUDE.md`는 미결 질문 4.
5. 최종 대조 → **팀장 보고 → 확인받은 뒤** 푸시·배포 → 라이브 대조(`curl`로 바이트·헤더,
   smoke-check).
